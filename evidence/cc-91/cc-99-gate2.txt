## Pass 1 — generic bugs (diff only, no intent)

Cold-read of origin/main...HEAD as code. No ticket text as spec.

Control flow (place_token / named_rows)
- named_rows is now one line: rank_matches(filter_rows(token, rows)).
  The previous path, when filter_rows of the full token was empty,
  retried filter_rows of token.split()[-1]. That retry is gone.
- _name_hit is unchanged: exact NAME head, head plus a Census class,
  or a later whole word in the head (West Springfield still matches
  springfield). Last-word retry was a second token, not that branch.
- _COUNTY no longer IGNORECASE on the whole pattern. Capture is
  Title Case [A-Z]..., then non-greedy (Title Case word | of | the |
  and), then (?i:count(y|ies)).
- County hit: split group 1, pop leading _TOKEN_NOISE, then if the
  first remaining word is not {all, every, each} return the joined
  remainder. Empty or all/every/each falls through to _PLACE_SPAN
  then leftover, as before.
- Call sites in geo.py are unchanged: default for_level, wildcard
  host, nested parent match (still filter_rows+rank_matches, never
  named_rows), NAME listing token then named_rows; place miss still
  retries the same token on the county listing.

Callers
- resolve_geography still passes find_state's name or None into
  place_token, then named_rows(token, rows). Empty named_rows still
  becomes specs=[].
- Nested leftover_parents still uses filter_rows, so it never had
  the last-word retry.

Missed cases checked
- "Harris County, Texas": _COUNTY group 1 is Harris; token harris;
  _name_hit("harris", "harris county") is head plus class; for stays
  county:201 in=state:48. Parametrized with the sentence form.
- "population of Harris County, Texas": Title Case Harris starts the
  county capture (lowercase "population of" cannot). Token harris,
  not the sentence. Control: named_rows("harris") still hits the
  Texas row in the fixture.
- "Population of Harris County, Texas": capture can start at
  Population (Title Case) and include "of Harris" before County;
  leading noise pops population then of; remainder harris. Same token.
- "Occupation breakdown for workers in Silicon Valley counties":
  detect_level sees counties -> county. _COUNTY cannot continue from
  Occupation through lowercase "breakdown for workers in". Match is
  Silicon Valley counties; token silicon valley. named_rows of that
  token does not retry valley, so Naugatuck Valley Planning Region
  and Valley County are not hits. specs=[].
- named_rows("silicon valley") vs fixture Valley* rows is [].
  Later-word _name_hit still needs the token as a whole word in the
  head; "silicon valley" is not that word.
- "all counties in Texas" / "All Counties in Texas": first remaining
  word all -> do not return from _COUNTY. Wildcard path unchanged.
- "vacancy in Isle of Palms": _COUNTY does not fire; _PLACE_SPAN
  still returns isle of palms (of allowed inside the span).
- "New York City" / "Austin, Texas" / "State College, Pennsylvania":
  leftover path unchanged; existing assertions still hold.
- All-lowercase "harris county": _COUNTY and _PLACE_SPAN both need
  Title Case, so leftover (strip county, then noise) still yields
  harris. Fail-closed Title Case is the same convention as the
  in/for/of span, not a new branch.
- Leading noise-only county capture ("The County"): words empty
  after strip; fall through. No published county in the fixtures
  starts with a _TOKEN_NOISE word.
- compare.py has its own _COUNTY; this diff does not touch it.

Incorrect control flow
- nothing. Last-word retry is gone for every named_rows caller.
  County still precedes the span extract. County now returns the
  name before count(y|ies) after stripping leading noise, so Harris
  does not depend on a last-word retry. Listing still ranks;
  specs[0] is still the pick when there are hits; zero hits stay
  empty specs.
