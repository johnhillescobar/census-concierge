## Pass 1 — generic bugs (diff only, no intent)

Cold-read of origin/main...HEAD as code. No ticket text as spec.

Control flow (place_token)
- _COUNTY.search still runs first. Named county not in {all, every, each}
  returns group 1 casefold. Regex and early return moved unchanged.
- New: _PLACE_SPAN finds Title Case spans after in / for / of.
  Negative lookahead skips (?:19|20)\d{2}. Name is group 2 (group 1 is
  the unused year capture inside the lookahead).
- If state_name is set, that name is stripped from each span; empty and
  state-only spans are dropped.
- Remaining spans: return the last one, casefolded.
- No span: leftover path as before (strip USPS, class words, state,
  _TOKEN_NOISE). Same word set that geo.py _NOISE still uses for _nation.
- Call sites in geo.py are unchanged: default for_level, wildcard host,
  nested parent match, NAME listing token.

Callers
- resolve_geography still passes find_state's name or None.
- Finish still dispatches resolve_geography with the original question
  when urls are missing. The new token is what lets NAME listing hit.

Missed cases checked
- Bare "New York City" / "Austin, Texas" / "State College, Pennsylvania":
  no in/for/of span; leftover path; existing tests still assert the old
  tokens.
- "population of Texas": span is the state, stripped, leftover returns
  texas; for_level stays state.
- "population of Harris County, Texas": _COUNTY still wins; token remains
  the greedy capture "population of harris". _PLACE_SPAN does not run.
- "of Phoenix in 2024": year span skipped; last remaining is phoenix.
- "in Ann Arbor ... in college": college is lowercase, not a span.
- "all counties in Texas": _WILDCARD sets for_level before listing;
  place_token runs on parent_text "Texas", host equals state.
- Two Detroit rows: filter_rows("detroit") hits both; rank_matches
  population then GEOID; specs[0] is the larger.
- No Title Case span (all-lowercase "in detroit"): leftover is the whole
  sentence; filter_rows of that token stays empty.
- After dropping a trailing state span, an earlier Title Case word after
  of (e.g. a group name) can remain as the token. That is the last-span
  rule on what is left, not a second branch. No NAME row in the new
  fixtures would match those leftover words.

Incorrect control flow
- nothing. County still precedes the span extract. Span extract returns
  only when a Title Case in/for/of name remains. Leftover is unchanged
  when it does not. Listing still ranks; specs[0] is still the pick.

Pass 1 findings: nothing.
