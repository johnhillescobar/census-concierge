## Pass 1 — generic bugs (diff only, no intent)

Cold-read of origin/main...HEAD. No ticket description as spec.

Control flow
- _kept_urls copies record.retained_urls, then fetch.urls, then str(record.url),
  wraps each extra through CensusURL, de-dupes, writes back onto the record.
- clear_series calls _kept_urls, then sets url/rows/table_id/universe/fetch
  empty. The keep and the wipe are sequential; no await between them.
- series_from_record also calls _kept_urls. Current built URL wins when
  present; else kept. If fetch is a FetchDataResult, artifact.urls wins when
  non-empty, else that fallback. Year buckets still come only from a live
  FetchDataResult; after clear they are empty lists.

Lost / dropped URLs
- A built URL or fetch.urls list is copied before clear_series wipes the
  pointers. assemble after clear ships kept rather than [].
- A successful current fetch still returns only artifact.urls, not the
  retained history. Same as before when a fetch artifact exists.
- Never-built still ships urls=[]. test_series_clear_without_a_built_url_stays_empty
  pins that.

Wrong fallbacks
- After resolve_geography changes the spec, assemble can ship the previous
  geography's URL as urls[0]. test_new_geography_clears_current_fetch_but_keeps_the_url
  asserts county:201 (Harris) after resolving Cook, with ambiguous_place.
  Rows are cleared, so no Harris numbers are returned as Cook's answer.
- geography_not_nested keeps the city URL (place:20000) when finish does not
  rebuild. That is a prior legal GET, not an invented nested for/in.

Record mutation
- retained_urls is not a field on ExecutionRecord. _kept_urls setattr's it.
  dataclasses.replace / asdict would drop it. series_from_record is a read
  used by assemble and it writes. Per-request record; no cross-request share.

Redaction / keys
- New keep path wraps CensusURL. Tests with &key=secret assert key= and
  secret are absent.
- When FetchDataResult.urls is non-empty, series_from_record still assigns
  list(artifact.urls) without wrapping CensusURL. Production _fetch_one
  already stores str(census_url). Not introduced here; the new fallback
  path does wrap.

Year buckets vs URL
- test_failed_fetch_survives_series_clear pins response.urls == retained URL
  and response.failed_years == []. The fetch artifact (failed_years=[2024])
  is discarded by clear_series. URL remains; series metadata does not.

Tests that cannot fail
- nothing. New tests assert concrete URL substrings, empty vs non-empty
  urls, and redaction. Renames of two existing tests flip [] to a kept URL.

Leaked keys
- nothing on the new CensusURL wrap.

Race
- nothing across requests. Keep-then-wipe in clear_series is synchronous.

Pass 1 findings:
- retained_urls is undeclared state; series_from_record mutates the record.
- After clear_series, urls[] can be non-empty while table_id, universe, and
  year buckets (including failed_years) are empty.
- Geography change ships the previous geography's URL as urls[0] with a
  warning about the new place; rows are empty.
- nothing else: no key leak on the keep path, no tests that cannot fail,
  no dropped URL on the four assemble-after-clear cases in the diff.
