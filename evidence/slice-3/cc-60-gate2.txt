code only; no knowledge of intent

1. _WITHIN + empty-requires ZCTA is a legal nationwide wildcard
   _WITHIN.search now ORs into the wildcard path. For "zctas inside Denver"
   and "zip codes inside Denver", detect_level("Denver") is None, so extra
   is empty. legal_predicate(zip code tabulation area, in={}, wildcard=True)
   succeeds because that level requires nothing. _arun then returns
   matches=[{for: zip code tabulation area:*, in: ""}], legal=True,
   nested=True. geography_not_nested never fires. The caller is handed every
   ZCTA in the dataset.

2. nested is True when the parent never made it into in_parts
   On the wildcard + predicate is None path, nested = not in_parents or all(
   nests_in(...)). Empty in_parts makes nested True. "tracts within Denver"
   (no city/county word) therefore comes back legal=False, nested=True,
   matches=[], detail "tract with in={} is not a legal combination".
   geography_unsupported fires; geography_not_nested does not. Same shape
   as an unsupported combination, not as non-nesting containment.

3. _ZIP matches the official Census geography name
   The ZIP regex matches the "zip code" inside "zip code tabulation area".
   A question that already used the ZCTA's published name still gets
   zcta_not_zip. The ZCTA-wording test uses "ZCTA 90210" and does not
   catch this.

4. _absorb reads nested only via getattr
   legal and detail use hasattr / dict.get. nested is
   getattr(artifact, "nested", True) is not False. A dict artifact with
   nested=False is stored as nested=True, so geography_not_nested would
   not fire. ainvoke currently returns ResolveGeographyResult, so this is
   latent on the live path.

Nothing else on this pass. No crash, no second URL formatter, no numbers
routed through the model, no blocking prompt. t16's "census tract within
the city of Denver" does set nested=False and returns matches=[].
