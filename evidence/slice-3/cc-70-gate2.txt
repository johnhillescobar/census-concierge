Pass 1 -- generic bugs

1. nests_in is applied on the non-wildcard path, so a named geography that
   mentions a state and does not nest in state no longer copies in=state and
   no longer fail-closes.
   api/src/geo.py:335-338. Non-wildcard sets host = state[0], so
   host in {"", state[0], "state"} is always true whenever a state was found.
   The old `if not host or host == state[0]` therefore always copied the FIPS.
   The new conjunct `nests_in(for_level, "state", entries)` skips that copy
   for zip code tabulation area. Execution then hits legal_predicate with
   empty in_parts and `wildcard or not in_parts` True, lists nationally, and
   token-matches. Measured with the test fixture:

   "ZCTA 90210 Oregon" -> legal=True nested=True specs=[(zip code tabulation
   area:90210, "")]
   "Median household income for ZCTA 90210 in Oregon" -> same

   Before this line, those queries copied in={'state': '41'} and failed as
   an illegal combination. After it, Oregon is dropped and 90210 ships.
   Tests only cover wildcard ZCTAs and named 90210 with no state, so this
   path cannot fail.

2. Leftover host is the literal token "state" only. "all counties in the
   Commonwealth of Pennsylvania" still fails nested=False with
   "county does not nest in (the Commonwealth of Pennsylvania)". Pre-existing
   for that phrasing; the new set does not generalize past one leftover word.

3. test_all_places_in_oregon_is_a_state_wildcard does not exercise the changed
   predicate. It is a lock of already-green Oregon place wildcards.
