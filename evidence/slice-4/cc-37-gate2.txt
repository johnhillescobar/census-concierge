=== Pass A — generic bugs (cold read of origin/main...HEAD, code only) ===

Diff read in full. Hunted: bugs, stale state, a11y, 422 mapping, plan POST
question, geography for/in text, blocking clarification, duplicated
AskResponse copies.

Findings:

1. 422 field `variables` is invisible while the editor is open.
   reject_unknown_override can raise loc=("body","plan","variables")
   ("invalid variables override"). fieldFromDetail returns "variables"
   because that token is in PLAN_FIELDS, so the /variable/i -> table_id
   fallback never runs. PlanStrip FieldNote only matches table_id,
   dataset, years, geographies. The catch-all role=alert while editing
   only renders when field is "" or "plan". Apply then looks like a no-op
   (prior dataset kept, no strip error). Same hole for loc-named
   allow_overlapping_acs5. table_id / dataset / years / geographies /
   body-only GEOID paths do map and display.

2. a11y: plan apply sets state to loading and App focuses
   "Looking up tables…". On 422/network failure that node unmounts and
   nothing moves focus to the invalid control or the role=alert. Inputs
   never get aria-invalid or aria-describedby.

3. a11y: related-table buttons expose only the table ID as the accessible
   name; title, universe, and reason are sibling spans, not tied to the
   control.

4. Stale chat error: runAsk(source="plan") never clears the chat-pane
   `error`. A failed later question (keepResult) then a successful plan
   apply leaves the old chat alert next to the new answer.

Hunted, nothing:

- plan POST sending the wrong question: onApply uses activeQuestion, not
  the chat input. New question submit passes plan=undefined.
- geography for/in text: no for=/in= textbox; picker is checkboxes over
  returned GeoSpecs keyed by GEOID.
- blocking clarification: none. Candidates ship on the result; picker is
  the strip, not a prompt before an answer.
- duplicated AskResponse copies: one result state. PlanDraft is form
  state derived from result.plan. Alternatives moved out of ActiveDataset
  into PlanStrip (one list). Chart/CSV still consume the same AskResponse.
