Independent manual cold read (same diff), supplementing the skill's pass:

  - web/src/csv.ts:6-9 (csvField): formula-like text (leading =, +, -, @) is
    written to CSV cells unescaped by design (csv.test.ts asserts this: "leaves
    comma-free, quote-free, formula-like text unescaped"). This is the classic
    CSV/formula-injection shape (CWE-1236) if a cell is ever attacker-influenced.
    Low practical risk here: every field in a DatasetRow (dataset, tableId,
    variable, geoid, name, universe) is Census-Bureau-controlled metadata or a
    NAME string from the Census API, never free text a user types. Noted as a
    hygiene follow-up, not a live vector today.
  - Column-order audit: CSV_HEADERS is
    ["dataset","vintage","period","table_id","variable","GEO_ID","NAME","estimate","moe","universe"]
    and csvRow()'s array is
    [row.dataset, row.year, row.period, row.tableId, row.variable, row.geoid, row.name, row.estimate ?? "", row.moe ?? "", row.universe]
    — positionally verified 1:1 against the ticket's required order
    (dataset, vintage, period, table_id, variable, GEO_ID, NAME, estimate, moe,
    universe). No mis-ordering found.
  - No bugs found in rowsToCsv's RFC 4180 escaping (quote-on comma/quote/CR/LF,
    doubled internal quotes, \r\n line endings) — matches csv.test.ts fixtures
    exactly, independently re-derived by hand against the sanitizeSegment /
    csvFilename regex.
  - No correctness bug in csvFilename's path-traversal handling: the allowed
    character set is [A-Za-z0-9_-] only (no '.', no '/'), so
    "../../etc/passwd" reduces to "etc-passwd", never a directory segment.
  - No mutation-shared-state bug: EstimatesTable and ResultChart both format
    DatasetRow.estimate/.moe for *display* (formatCensusNumber, chart.ts's
    num()) without writing back onto the row objects; rowsToCsv reads the same
    array's raw fields, so a comma-grouped display number can never leak into
    a CSV cell (verified by reading web/src/display.ts, web/src/chart.ts, and
    the EstimatesTable render body).
