Interpolation of gaps: nothing.
  Line path walks every calendar year between min and max; a missing year or
  a null/non-numeric estimate increments `segment` and is not pushed.
  Null estimates are omitted from line points (not replaced with 0).
  Layer uses `detail: { field: "segment" }` so Vega does not connect across
  the gap. Test: 2019 / sentinel 2020 / 2021 → segments 0 and 1, no zero.

Wrong MOE: nothing.
  `low`/`high` are estimate ± moe. Missing estimate or missing moe → null
  bounds, not 0. `isChartSpec` requires `show_moe === true`. Errorbar layer
  is always present on a drawn spec. Table still renders matching MOE.

Leaking data.url: nothing.
  Vega spec is built in `vegaSpec()` with `data: { values: points }` only.
  ChartSpec fields are read by name; extra `data.url` on a sneaky object is
  not copied. Test asserts JSON has no `"url"` key and drops example.invalid.

Enabling Vega actions: nothing.
  `EMBED_OPTIONS = { actions: false, renderer: "svg" }` and ResultChart
  passes that object into `vega-embed`. Test asserts the constant.

Raising budgets: nothing.
  `budgets.toml` is not in the diff. `check_invariants --base origin/main`
  reports `ok budget increases`. web src LOC 2957 <= 3000.

  App still renders EstimatesTable, census URLs, GEOID, universe.

Security: nothing.

Other (not blocking):
  1. Line `byYear.set(year, row)` last-wins. Two rows in the same series
     and year keep one point. Backend `take_chart` (not in this diff) sets
     `series_by: geography` on its own fallback when there are multiple
     GEOIDs, but a model ChartSpec with `series_by: null` and multiple
     geos would still validate there and collapse here. Table stays complete.
  2. x encoding is ordinal with no `sort`. A single series is emitted in
     year order; two series with disjoint years can get first-seen x order.
  3. Geography x/series labels are `name || geoid`, not GEOID. Homonymous

  4. ResultChart has no rejection handler on `import("vega-embed")` /

     executed in unit tests.
