Findings:

- geo.py find_state() matches full state names before USPS codes. "Washington, DC"
  matches state name "washington" (FIPS 53) and never reaches the ", DC" branch.
  Default for_level is place; place_token then strips "washington" and ", DC",
  leaving an empty token; filter_rows("") returns every listed row. Result: a DC
  query lists (or later fetches) places in Washington state.

- geo.py place_token() strips the matched state name and the word "city".
  "New York City" becomes an empty token after "new york" and "city" are removed;
  filter_rows("") again returns the entire listing (every place in New York
  state). Same empty-token dump for any query whose only remaining tokens were
  the state name.

- geo.py detect_level() has no hit on a bare state ("population of Texas");
  ResolveGeographyTool then sets for_level = "place". Combined with the
  empty-token behavior above, a state-only query lists places rather than
  returning for=state:XX.

- geo.py list_census_names() puts key= on an httpx params dict, not through
  CensusURL. raise_for_status() on that request can raise httpx.HTTPStatusError
  whose str() includes the full URL with the key. ask.py dispatch() sends
  "{name} failed: {exc}" back to the model. fetch_data exception detail=str(exc)
  has the same hole if httpx includes the with_key() URL.

- tools.py BuildUrlTool interpolates model-supplied for_spec / in_spec into the
  Census URL with no check against resolve_geography matches. in_spec="" (not
  None) also overrides a resolved in= parent. Geography codes from the LLM go
  on the wire.

- ask.py _absorb(search_tables) writes record.table_id / universe from hits[0]
  before any build_url. assemble() will name a table on a loop that never built
  a URL. Family-member picks (e.g. B19013A) never match hit["table_id"], so
  universe stays the parent/first-hit string; availability.table_facts already
  has the member universe and is unused.

- ask.py assemble() sets geoid from rows[0] only. State fast-path and wildcard
  matches store geoid="". A failed fetch after a successful resolve/build
  therefore returns geoid="" even when FIPS is known.
