### The claim

**What can a user do now that they could not before?**

A developer (or downstream slice-1 agent) can pass a natural-language Census question to `search(question, k)` and receive ranked ACS table IDs from a built offline index; `scripts/eval_retrieval.py` scores retrieval against 66 golden questions and records retriever `@10`, selector `@1`, and synthetic alignment in `evidence/latest.json`.

This is infrastructure for discovery, not an end-user answer — no agent, URL, or data fetch yet. That matches slice 0 scope.

### Silent-wrong-answer review

**Nothing on a user response path** — slice 0 has no URL/MOE/GEOID/universe rendering.

Relevant retrieval-side protections present in diff:

- `build.py` drops table families with no base representative (avoids ranking a race iteration as the general table).
- `is_subject_table` excludes B00/B98/B99 survey-quality tables.
- `_fold_identical_twins` removes byte-identical C twins that would win/lose by float noise.
- `rerank.py` refuses hallucinated table IDs not in the candidate list.
- `embedding.py` aborts on batch length mismatch (prevents shifted embeddings).
- No `&key=` handling in this slice (no Census fetch URLs constructed).
