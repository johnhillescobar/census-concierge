(identical inputs ranked by float noise, a family returned by one member, a ranking change
measured on the tuning set alone, "expect the largest jump" checked against the number). None of
them targets answer figures, so the probes come from the ticket's test classes (happy, edge,
novel, regression, failure) and from the failure modes of the check itself. Section 3 is that
set, 58 probes, in evidence/slice-6/gate1-probes.py. No eval phrasing is used or added anywhere.

What the first mutation run and the sweep found about the TESTS (fixed in the tests, no source change)
  - Since the Gate 2 fix a digit-bearing token that float() cannot read is flagged, so taking one
    mark ($ % * ( " ;) or one separator (- en dash em dash / |) out of the stripping lists no longer
    lets a stray figure through: the 12 old "flag" tests could not fail by one revert. What
    the lists protect now is a CARRIED figure written with a mark, or a carried range: no test said
    so. Added test_marks_around_a_carried_figure_do_not_change_it and
    test_a_range_of_two_carried_figures_passes_whatever_the_separator. The old tests stay, checked
    against the pre-fix state (the mark taken out AND unreadable tokens skipped).
  - test_a_label_loses_its_estimate_prefix_and_joins_its_levels never offered a variable nobody
    asked for, so _labels returning every variable passed. Added
    test_labels_come_back_only_for_the_variables_asked_for.
  - Nothing pinned: the stand-in for a dropped text being non-empty; thousands separators on a figure
    that is not rendered (the cap cut it); the notice at exactly 20 figures (>= instead of >);
    table facts being asked in the row's own dataset (every stub ignored the dataset); years of a
    shared description joined with ", "; the five-number limit and comma of the notice; the join of
    two notices; a notice joining a warning of another code (the one branch coverage showed);
    _shown's fallback for a cell that is not a number (N, (X), 250,000+). Tests added for each.
  - The first fixed-point fuzz was vacuous (the rendered lines are what it was compared with). It
    is now a property test: any cell of the response may be quoted and is never flagged, every
    shown cell appears as the Census sent it, a sentinel never appears.
  - test_a_real_record_carries_what_the_check_reads_from_it runs the real ExecutionRecord,
    CensusURL, RequestLeg and FetchDataResult: every earlier test reached them through
    SimpleNamespace, which cannot notice a renamed attribute.

DEFECTS AND FOLLOW-UPS IN THE SOURCE (reported, not fixed; api/src is untouched)
  D1  blocks by the Gate 2 rule (a figure passes unchecked; the prompt already bars shares, so
      the owner may rate it a follow-up): a numeric character that is not a decimal digit is not read as
      a figure, because _numbers looks for str.isdigit(). "About ½ of households", ¼, ¾, ⅔ and
      Roman numerals pass the check unchanged (probes B01 to B05). The prompt bars shares, so the
      model should not write them; the point of the check is the case where it does. Four strict
      xfail tests (test_a_fraction_character_is_a_figure_too) hold the correct behaviour; changing
      isdigit to isnumeric in _numbers turns all four into strict XPASS (section 7, FIX lines).
      Words ("half", "seventy-six thousand") are not covered either; that is the owner's decision
      (no word list) and is named as a gap, not a defect.
  F1  follow-up (false positive, the framing is replaced): the omission reason code in the fetch
      summary the model sees, "omitted 2020:vintage_gap_2020", holds a year and is not among the
      carried tokens, so a framing that quotes it ("2020 was omitted (vintage_gap_2020)") loses its
      text (probe E04). The status codes of the same summary ARE carried, which is the Gate 2 fix B4.
      One strict xfail test; carrying fetch.omission_reasons turns it into XPASS.
  Observations, no test, for the owner or Gate 2 to weigh
  O1  An estimate whose margin column is absent from the row renders "margin of error not
      published" (probe G01): that claims the Census did not publish it, when the column simply
      was not fetched. The pipeline fetches M with every E, so this needs a fetch that dropped it.
  O2  A row holding estimates of two tables names only the first table (probe G02; the plan's N3).
  O3  Text that states only response data is replaced when it: ends a number with the ellipsis
      character (E01), uses an ordinal ("the 2nd table", E02), pastes the Census URL (E03), or
      repeats the fetch summary's own counts, "2 rows over 1/1 legs" (E05). Conservative, not a
      silent wrong answer; the E2E fallback rate is where it shows.
  O4  The "texts" half of what _render returns is redundant with "lines" (2 of the 5 final sweep
      survivors delete part of it with no change in behaviour); a simplification, not a defect.
  Known gaps, named in the plan and not tested as solved: a framing that attaches a carried number
  to the wrong place (D01) or the wrong sign (D02, abs() is used), a carried number that means
  something else, a state FIPS of 17 carrying "17 percent" (D03), the dataset's 5 carrying "5
  percent" (D04), numbers written in words (B06, B07).
  Equivalent or wording survivors of the final sweep, read and left: texts.append(label) deleted
  (the label is also in "lines"), texts += list(about) deleted (same), the " " inside the digits of
  a dataset name (every dataset name has one group of digits), and the wording of the notice
  (the repo bars tests on prose).
