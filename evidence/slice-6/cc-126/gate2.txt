What was checked and did not fail:
- httpx.Client(timeout=None) stores Timeout with connect, read, write, and pool all None. The sync backend passes that None to socket.create_connection and socket.settimeout, which is a blocking socket with no phase deadline. The only deadline is threading.Timer calling Client.close. ConnectionPool does not hold its lock across handle_request, and HTTP11Connection.close closes the socket without waiting for the read.
- A local _download GET (no injected getter) returned a body that response.json() could read after the worker closed the client. A peer that accepted and never answered raised httpx.TimeoutException "census total deadline exceeded" at the total budget (1.017s for total=1.0). The key was not in the message. No census client thread was still alive after return. A fast hedge response was returned at the moment that response finished; join of the loser did not add a further second.
- Tight totals (0, 0.001, 0.05, 0.2), eight tries each, raised only TimeoutException or ReadError. Both are httpx.HTTPError, which fetch._fetch_one and geo_list.list_census_names already catch. No RuntimeError and no key in the message.
- One backup, never a third. A connection failure before the hedge waits only for the backup. A primary still running at the hedge waits for both, and the first httpx.Response wins, including a non-200. That is what the module text and the tests lock in. ConnectTimeout, NetworkError, and ProtocolError count as connection failures; other TimeoutException subclasses do not. ReadError is a NetworkError, so a reset before the hedge is retried once. With phase timeouts disabled, the production client does not raise ReadTimeout.
- _download reads the body before the worker closes the client and queues the attempt. _reraise redacts &key= in HTTPError text and re-raises the original when the text is unchanged. fetch stores redact_text(str(exc)) on the leg. geo_list turns HTTPError into RuntimeError containing the CensusURL, which has no key, and uses "from None". The key is attached only by CensusURL.with_key.
- fetch still enters _census_get through asyncio.to_thread under Semaphore(5). The hedge is a second connection inside one leg. No httpx.get remains under api/src. FetchDataTool.http_get still skips _census_get. The two geography-listing tests now patch src.census_http.census_get.
- latency_probe install_spans wraps census_http.census_get, which is the attribute fetch and geo_list call, so one hedged GET is one census span. cmd_replay's _get still calls httpx.get(timeout=60) for direct URL replay. That helper is not the ask path, and this diff does not change it.
