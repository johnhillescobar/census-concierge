## Problem

In the UI, clicking one of the alternative ("close") tables after a listing question fails with `422 Unprocessable Entity` on `POST /conversations/{id}/turns` (and `POST /ask` with a plan). The server's message is `geography override requires an executable GEOID`. After a single-place question the same click works (200).

Found while preparing a demo after CC-103 merged. Not caused by CC-103: it reproduces on the pre-CC-103 baseline (`7b406f2`, which has no split call), and CC-103 changed neither `api/src/contract.py` nor the front end. CC-103 only makes listing results (all-wildcard plans) more common, so more people will hit it.

## Cause

`web/src/PlanStrip.tsx` calls `applyPlan(tableOverride(result.plan, alt.table_id))`. `tableOverride` (`web/src/plan.ts`) spreads the whole previous plan, including `geographies`. `AskRequest.bind_plan_geographies` then calls `bind_override_geographies` (`api/src/contract.py`), which rejects any geography whose `geoid` is not a single executable GEOID. A wildcard geography (`for_spec` ending in `:*`) has an empty `geoid`, so the model validator raises and FastAPI returns 422.

## Options

1. Front end: when only the table changes, do not resend wildcard geographies; the server re-resolves them from the question.

2. Server: let `bind_override_geographies` accept a wildcard geography by binding it from its `for_spec`/`in_spec` when the GEOID is empty. This fixes every client at once and is the recommended direction.

## Acceptance

- Clicking an alternative table after (a) a one-parent listing, (b) a multi-parent listing, and (c) a single place all return 200, with the new table and the same geographies.

Why this is important

A selectable alternative must recover a useful answer, not merely return HTTP 200 or avoid the wildcard 422. A new table may require different cells; blindly preserving old variable identifiers can produce a valid-looking wrong answer.

Acceptance criteria additions

AC1. Alternative selection preserves unaffected requested meaning: geography identities, scope, parent chains, product and years. Validate or reselect cells against the selected table's metadata and measure/universe intent; do not reuse incompatible old-table variable IDs or silently substitute a total. Preserve a variable only when its semantic compatibility is established. This clarifies older 'zero loss of variables' wording.

AC2. Before executing an alternative, validate its table/cells, universe, vintage availability and geography chain. A displayed executable alternative URL must have these checks and match the request actually sent. A discovery-only candidate is explicitly not yet validated; unavailable/incompatible alternatives disclose the limitation and never masquerade as an answer. Live prefetch of every candidate is not required.

AC3. Add end-to-end alternative recovery journeys: wrong primary choice with a correct offered alternative, selecting that alternative, and receiving the independently expected data/answer. Record all attempted selections, failures and elapsed time from selection to result. Coordinate scoring with CC-132; passing an override transport test alone is insufficient.

Test cases additions

TC1. Select the correct offered alternative after an incorrect primary answer for named, wildcard and multi-parent geography; assert expected cells/data, every requested leg and faithful vintage/product, not just status 200.

TC2. Switch to a table with incompatible cell identifiers or universe; grounded reselection succeeds or a specific limitation appears, without reusing stale cells or silently returning the total.

TC3. An alternative exists in the catalog but not the requested vintage/geography: distinguish discovery from executable status, preserve requested intent and never label the incompatible URL validated. A validated URL and executed HTTP request agree.
