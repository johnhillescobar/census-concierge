Retained scope and acceptance criteria (read with the binding alignment above)
## Overview

Enable analyst-grade requests that cannot be expressed through Census `for`/`in` nesting, beginning with “all ZCTAs in Chicago.” Add a versioned place-to-ZCTA crosswalk, distinguish whole intersecting ZCTAs from city-clipped estimates, and support retrieval of every published estimate/MOE cell in an ACS table.

This is an intermediary epic of phase 1 (through slice 8), not future or phase 2 work. Its CC-11 foundations (table rendering and the editable plan strip) have shipped and CC-73 is Done, so it can be scheduled within phase 1. It revisits the recorded deferrals in CC-55 and CC-56 using explicit failing golden questions; it does not silently bypass them.

## User outcome

A researcher can ask for all ZCTAs associated with a named Census place, inspect the exact inclusion rule and overlap evidence, retrieve a complete ACS distribution table for those geographies, and—only where statistically defensible—request values allocated to the portion inside the place boundary. Every output remains reproducible from versioned source data and complete URLs.

## Scope

- Place → ZCTA crosswalks, generalized beyond Chicago and keyed by Census place GEOID.

- Evidence-earned place/gazetteer lookup integrated with existing geography resolution.

- Versioned block-level spatial relationship artifacts and documented overlap thresholds.

- Whole-ZCTA results versus city-clipped/allocation results as separate, explicit modes.

- Full ACS distribution-table retrieval: all published estimate variables and paired margins of error, split across request legs when Census URL/variable limits require it.

- A fifth agent tool only if a named golden question proves the four existing tools cannot represent the operation cleanly.

## Acceptance criteria

- [ ] A new long-tail golden question for “all ZCTAs in Chicago” fails before implementation and passes afterward.

- [ ] The response returns a deterministic, versioned set of Chicago-associated ZCTAs with ZCTA GEOID, place GEOID, overlap measure, inclusion rule, source vintage, and no claim that ZCTAs legally nest in places.

- [ ] At least one second city with boundary-crossing ZCTAs proves the implementation is general rather than Chicago-specific.

- [ ] Whole intersecting ZCTA estimates are clearly distinguished from values allocated to only the city-intersection portion.

- [ ] Block allocation is enabled only for measures with an approved mathematical basis; medians, ratios, and other non-additive statistics are rejected unless a reviewed method exists.

- [ ] Allocation output includes method, weights, source geography/vintage compatibility, uncertainty limitations, and component provenance; no allocation is presented as a published Census value.

- [ ] A request for a full ACS distribution table returns every published `E` variable requested by the table and its matching `M`, with deterministic column order and complete redacted URLs for every chunk.

- [ ] Chunked request legs join only after geography keys and row cardinality match; partial failure retains successful chunks and identifies missing variables/URLs.

- [ ] Every row retains GEOID, universe, dataset, vintage, table, variable provenance, and relevant warnings.

- [ ] Existing `geography_not_nested`, `zcta_not_zip`, median, MOE, vintage, and boundary guards remain intact.

- [ ] No fifth tool is added unless the tool-decision story records a specific failing golden question, demonstrates why parameters on existing tools are insufficient, and passes all tool/model/latency budgets without raising them.

- [ ] `make check`, retrieval evaluation, and `make demo --repeat 3` pass existing floors/ceilings with no budget raised.

## Dependencies

- CC-2 complete, including CC-73 multi-geography request legs.

- CC-11 foundations, especially CC-35 full dataset table and CC-37 editable plan strip, available before user-facing closure.

- Existing CC-55 and CC-56 decisions explicitly revisited by evidence, not treated as feature tickets.

## Out of scope

- Treating USPS ZIP routes as interchangeable with ZCTAs.

- Inferring legal Census nesting where none exists.

- Naive population weighting of medians, percentages, or ratios.

- A generic routing graph, clarification subsystem, or new API route per internal tool.

- Raising any budget.
