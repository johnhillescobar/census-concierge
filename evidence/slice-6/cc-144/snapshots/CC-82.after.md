Retained scope and acceptance criteria (read with the binding alignment above)
## Definition

A request for a full ACS table, or for more than 24 estimates, returns every requested published cell with matching margins, stable column order and all source URLs, for every requested geography and vintage.

## Why it matters

Researchers outside their specialty want the whole table, not `001E`. CC-77 is a phase 1 intermediary epic. Live pre-flight (ACS5 2023, 2026-10-04) shows `get=group(TABLE)` works with standard `for`/`in` and returns the whole table in one call: one state, a state list, all counties in a state, tracts in a county (about 2,500 rows), a named place, and all 3,222 US counties (200 columns, 4.1s). It returns E, EA, M and MA plus `GEO_ID`, `NAME` and the geography code, with identical columns across 2015, 2019, 2021 and 2023. ACS1 2020 returns 404 as expected. The `get` cap is 50 variables including `NAME` and `GEO_ID` (CC-118), so chunking is needed only where `group()` cannot be used.

## Scope

- Pre-flight first. Confirm `group()` for: single and multiple geographies, wildcard listings, multiple vintages, ACS1, tables with different column counts, and response size and latency for the largest realistic request. Record the result in `evidence/`.

- Mechanism. Use `group(TABLE)` as the variable clause where it works. Where it cannot be used, expand the selected group from cached metadata, classify its published data variables, split them into legs of at most 48 data columns (50 minus `NAME` and `GEO_ID`), and join chunks by geography keys.

- Large responses are bounded by a documented size limit with a clear message, never a timeout.

## Acceptance criteria

- [ ] A “full table” request returns every published data variable supported by the declared mode; at minimum every `E` is paired with its corresponding `M`, and annotation variables are classified, labeled and retained when full-variable mode requests them, never mistaken for data.

- [ ] Variable labels, concepts, universe, suffix/type, dataset, vintage, and table provenance accompany the returned schema.

- [ ] Each request, `group()` or chunk, retains its complete key-redacted URL and respects the live Census variable limits.

- [ ] Where chunking is used, chunks include stable geography keys and join only when GEOID/key sets and row cardinality are compatible; duplicate, reordered, missing, or extra geography rows fail safely rather than producing shifted columns.

- [ ] A failed request or chunk preserves successful variables and reports exactly which variables and URL failed; no missing columns are silently presented as complete.

- [ ] Column ordering follows authoritative group metadata deterministically.

- [ ] Named geography, legal wildcard, multi-geography, and multi-year cases are covered without multiplying calls unnecessarily; a vintage where the table's variables differ is named, never interpolated.

- [ ] UI/export consumers can distinguish complete, partial, and unavailable tables.

- [ ] Tests use at least one large distribution table, and at least one case that needs chunking, and mutation-check completeness and (where used) chunk joining.

- [ ] Existing URL, MOE, GEOID, universe, alternatives, secret-redaction, latency, and budget guarantees pass unchanged; no budget is raised.

## Test cases

- Happy: whole table for one state.

- Edge: all tracts in a county with a large table.

- Novel: a table in no existing eval, two geographies, two vintages.

- Regression: an ordinary single-variable request still returns one URL with `NAME,GEO_ID,E,M`; CSV export and table rendering at about 200 columns.

- Failure: a table absent in one requested vintage; the gap is named.
