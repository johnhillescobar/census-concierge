## Context

Narrowed from the original "resolve follow-up references" scope, which had no size limit. This ticket only gets the prior turn into the loop. The two kinds of follow-up are CC-107 (geography swap) and CC-108 (variable addition); unresolvable references are CC-39. Measured with CC-42.

## Acceptance Criteria

- [ ] `run_ask` accepts the prior turn's `ResultPlan` and question, read from the stored turn (CC-41 turns endpoint passes them).

- [ ] The prompt carries them as a structured block (table, variables, dataset, years, GEOIDs, geography level), never the rows.

- [ ] No regex or keyword table interprets the follow-up; the model composes the new plan through the existing tools and code only validates it.

- [ ] With no prior turn, the assembled prompt structure is identical to today's (test on structure, not wording).

- [ ] `POST /ask` behavior is unchanged (no prior turn is available there).

- [ ] The multi-turn rate at `--repeat 3` is recorded next to the CC-42 baseline.

- [ ] `make demo --repeat 3` single-turn long_tail answered_rate, at the same `--repeat` and the geography-level scorer, is no more than 3 points below the 0.742 baseline (>= 0.712) and no more than 3 points below this ticket's own pre-run; both runs are reported. Same-code runs vary by about 2 points (0.725 vs 0.742), so one run is not a verdict. Scoreboard quoted in the PR and again post-merge.

- [ ] p95 is recorded before and after; any increase is attributed to the prior-plan prompt block with the measured `t_llm` delta, since p95 is already over the 20s ceiling (CC-113).

- [ ] `make check` passes with `budgets.toml` unchanged.

## Test cases

- Happy: a stored prior ResultPlan reaches the ask loop as a structured block without rows and enables a measured follow-up.

- Edge: with no prior turn, prompt structure and POST /ask behavior remain identical to the existing single-turn path.

- Novel: a prior plan with multiple geographies or vintages from metadata is carried without prose parsing.

- Regression: conversation create, append, read, and ordinary single-turn routes continue to pass unchanged.

- Failure: malformed or forged prior-plan fields are validated and fail safely rather than entering the prompt or tools.
