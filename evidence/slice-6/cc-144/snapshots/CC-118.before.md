Retained scope and acceptance criteria (read with the binding alignment above)
## Definition

`build_url` never reports success for a request whose `get` clause would exceed Census's 50-variable limit, counting `NAME` and `GEO_ID`.

## Why it matters

The URL is the product. Today `build_url` reports `ok=True` for a URL the API rejects. Live evidence (ACS5 2023): 48 data columns plus `NAME` and `GEO_ID` succeed; 49 fail with HTTP 400 "'get' is limited to 50 variables". `build_url` always adds `NAME,GEO_ID` and pairs every E with its M, so the maximum is 24 estimates. Run through the real tools, 25 and 30 estimates both returned `ok=True` and then `fetch_data` failed with HTTP 400.

## Scope

Count the unique columns that will be sent (`NAME`, `GEO_ID`, every E and its paired M) before returning. Over the limit: return `ok=False` with a detail naming the requested count, the limit (50) and the maximum (24 estimates). The failed result still carries the over-limit URL for inspection, redacted as always. Splitting into legs and `group()` belong to the whole-table story under CC-82.

## Out of scope

Splitting into legs. `group()`. Changing how E/M pairing works. Raising any limit.

## Dependencies

None.

## Acceptance criteria

- [ ] 24 estimates: `build_url` succeeds and `fetch_data` returns rows (live).

- [ ] 25 or more estimates: `build_url` returns a failure naming the limit and the maximum, and no fetch is attempted on it.

- [ ] The over-limit URL is shown with a warning, never silently dropped.

- [ ] A request that already includes M variables counts unique columns, not requested ones.

- [ ] No budget is raised.

## Test cases

- Happy: 24 estimates, live 200.

- Edge: 12 E plus 12 M requested explicitly (24 unique pairs).

- Novel: a different table with 25 estimates.

- Regression: a 1-variable request and the CC-100 list are unchanged.

- Failure: 30 estimates; the response states the limit and the model can retry with fewer.

## Evaluation evidence

Unit tests mutation-checked by removing the guard. One live run showing 24 passes and 25 fails at build time before any HTTP call.

## Regression risks

Existing demo questions that already request more than 24 estimates would now fail earlier; check the demo for any. `tools.py` line budget.
