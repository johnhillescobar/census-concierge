U1  SHOULD (leans BLOCKER)  api/src/geo.py:142-145 (_written), :343, :251-253
    A state the user wrote is dropped whenever the report is unknown, and the wrong place is then
    selected. _written() treats states_named() == None ("no report yet / report failed / key omitted")
    the same as "the user wrote no state": `wrote` is empty, so every state attached to an entry fails
    the check and is discarded (docs/ask-path.md says this on purpose: "unknown is not written").
    Failing inputs (probe p1.py through run_ask, real tools, scripted model):
      question "Population of Portland, Maine", model sends places=["Portland, ME"], level place.
        report states_named=["ME"]      -> place:60545 in state:23 (Portland ME), no warning. Correct.
        report omits states_named       -> URL for place:59000 in state:41 (Portland, OREGON); only warning
                                           ambiguous_place. The user wrote Maine and got Oregon.
        split call fails / times out    -> same: Oregon.
      "Springfield, IL" with a missing report: all Springfields tie, so a refusal with no URL for a
      question whose state was written (false refusal; a late report, the 3 s FRAME_WAIT, a JSON error,
      or a model that leaves the optional key out is enough).
    Comparison (probe p3.py): places ["Portland, ME","Portland, OR"], states_named None or []:
      specs = [Portland OR, Portland OR, Portland ME, Portland ME] (compare_count 2) -> the comparison
      is Oregon against Oregon; state_supplied is False because _compare_result never carries it.
    Why it matters: the product renders a URL, and the rule here is that a state the user typed is the
    strongest evidence of the place. An absent report is a missing instrument, not a reading, so
    dropping the user's state turns a degraded report into a wrong-place URL. Fix direction: when
    states_named is None keep the entry's state (the old behaviour), and drop it only when a report is
    present and does not list it; or when unknown, return the candidates rather than a dominant pick.
    Also carry state_supplied through comparison and listing results.

U2  SHOULD  api/src/ask.py:361-363 with api/src/tools.py:312-325
    "Nothing is selected, built or fetched" (docs/ask-path.md, docs/requirements.md, ambiguous_place)
    is not enforced. _absorb clears record.geography for an ambiguous result, but build_url's
    allowed_geographies is built from record.geographies, which holds every candidate, and build_url
    accepts any for_spec/in_spec in that set. Probe p2.py "amb-pick": question "Population of Springfield",
    resolve_geography -> 3 Springfield candidates, geography None; the model then calls
    build_url(table_id=B01003, for_spec="place:72000", in_spec="state:17") -> URL built, fetch_data
    runs, a URL and rows for Springfield IL come back with only an ambiguous_place warning.
    Without a for_spec build_url refuses (amb-nopick, correct). The prompt tells the model not to pick,
    but the code is the control (and the owner edit to CLAUDE.md says an ambiguous question is as
    unsearchable as an incomplete one). Fix: allowed_geographies returns the empty set while
    geo_status.ambiguous (or build_url refuses on it); add a real-chain test.
