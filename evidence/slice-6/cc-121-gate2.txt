      _labels catches only OSError. A truncated/corrupt data/raw/<ds>/<yr>/variables.json.gz raises
      EOFError, zlib.error or json.JSONDecodeError (not OSError). The exception escapes _arun AFTER a
      successful Census fetch; dispatch swallows it as "fetch_data failed: ...", _absorb never runs, so
      record.rows/record.fetch stay empty (probe S5). finish_tools then retries fetch_data, it fails a

      metadata cache, so a cosmetic label lookup can now destroy a good fetch. Failing input: any
      question whose fetch succeeds while variables.json.gz for that dataset/year is corrupt.

P1-2  MEDIUM  api/src/fetch.py:199-201
      The 20-figure cut is row-major over every E key of every row, and rows are geo-major then year
      (fanout order). Multi-variable x multi-year x multi-place results hide whole places: 3 places x
      2 years x 8 vars -> only Place A and part of Place B shown, Place C absent (probe S2). Combined
      with the new prompt sentence "If the question asks about something that was not fetched, say
      so", the model is set up to claim Place C was not fetched when it was. "the rest are in the
      rows" refers to rows the model never sees.

P1-3  LOW-MEDIUM  api/src/fetch.py:438 (_labels called inside async _arun)
      metadata.variables gunzips and parses the whole variables file on every fetch_data call
      (81-137 ms measured, more for acs1), synchronously on the event loop -- not via asyncio.to_thread
      like the HTTP legs. Blocks concurrent /ask requests and the CC-103 split task; repeats when
      finish_tools re-fetches. Also inconsistent with the tool's injected-callable pattern
      (table_facts, published): labels reach the module directly, which is why the test monkeypatches
      fetch.metadata. (A module-level lru_cache would be a second module cache; ARCHITECTURE.md:66-67
      sanctions only the index.)

P1-4  LOW  api/src/fetch.py:435-438
      year = max(result.attempted_years) is used for labels and universe even when that year's legs
      failed (probe S6: 2024 ok, 2019 failed -> fine here, but the reverse picks a failed vintage), and

      or per-row year. Low impact while the cache covers every attempted year.
