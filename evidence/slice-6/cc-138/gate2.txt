PASS 1 — GENERIC BUG REVIEW

[P2] Reject malformed tool arguments before invoking an all-optional tool
(api/src/ask.py:312–318, api/src/ask.py:439–446).
Both invalid JSON and valid non-object JSON are treated as {}. Default
fetch_data accepts {} (api/src/fetch.py:34–41), so a completed provider turn
with malformed arguments can fetch the current URL or default vintage
rather than returning a validation error for the model to repair. The
new behavior includes converting non-object JSON to {}; invalid JSON
was already converted on the base. The added test uses a required
argument, so it observes validation even though an all-optional schema
would dispatch. Confirmed with the real SDK and a MockTransport response
containing arguments "{" for an all-optional year tool. It executed with
the default year 2024. Preserve the distinction between invalid and
intentional {} and send a failure output for the original call ID.

[P2] Handle transient provider errors at the model-call boundary
(api/src/ask.py:297, api/src/ask.py:451–453).
The base SDK client retries temporary 429/5xx errors (SDK 3.0.0 defaults
to two retries). This client takes one attempt. Provider API errors escape
the loop's RuntimeError handler, skip finish_tools, and cause /ask to
return a server error before it can assemble earlier tool results. A
MockTransport 503 on the first main request reproduced InternalServerError
after one attempt, though the mock could succeed on a later attempt. A
bounded recovery or degraded response is needed if the single-attempt
limit is retained.

[P2] Surface incomplete output instead of returning an empty success
(api/src/ask.py:308–309, api/src/ask.py:430–433).
The API's incomplete status (for example, a turn reaching the new
max_output_tokens ceiling) becomes indistinguishable from a normal
empty completion. Earlier answer text is replaced with an empty string.
The existing finish path can recover some data, but a no-data path can
return HTTP 200 with an empty answer and no warning. Confirmed by a mock
max_output_tokens response: answer '' and warnings []. Stop executing
partial tool calls and give the caller a meaningful failure or partial
result.

Open provider contract question (api/src/ask.py:298–307, 434–435).
With store=False, Responses documents include=["reasoning.encrypted_content"]
for stateless reasoning continuity. This request does not set include
and the fixture's replayed reasoning item contains no encrypted state.
The installed SDK also describes that field as populated by default
on returned reasoning items. The offline probe confirms the missing
request field and placeholder replay, but does not establish live
server behavior. Verify whether encrypted state is returned by default
and survives a Sol tool continuation; make the include explicit if needed.
