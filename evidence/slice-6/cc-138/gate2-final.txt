The client uses store=False and manual replay with no prior response ID. It does not request include=["reasoning.encrypted_content"]. The installed SDK's ResponseCreateParamsBase.include documents that this option enables reusing reasoning items in stateless multi-turn conversations. Replaying item IDs and summaries alone cannot carry the original reasoning across tool calls. The normal request requires multiple calls for search, resolve, build and fetch. Require stateless replay with the encrypted content for the reasoning model, and make the wire test assert that it is requested and propagated. The test currently sends an empty-summary reasoning item and accepts it on follow-up regardless of whether it can be replayed at the actual provider.

[P2] Null tool arguments still produce an invalid Responses continuation (api/src/ask.py:315-322).
Dispatch now rejects null and emits a tool validation result, but exclude_none removes arguments from the replayed function_call. The installed SDK's ResponseFunctionToolCallParam requires arguments to be a string. The next HTTP request therefore has a function_call missing a required field and can be rejected before the model receives the validation result. The null-wire fixture expressly accepts completion with that field missing (api/tests/test_ask_responses.py:172). Keep rejection of malformed input local, but construct a schema-valid continuation and check the actual follow-up payload against the provider input shape.
