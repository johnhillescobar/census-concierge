# CC-121 decision 1: "numbers never pass back through the model" (advisory, owner decides)

Rule: `docs/playbooks/review-pr.md:63-64` "Do numbers ever pass back through the model? The model names `B01003_001E`; it must never handle the value." CC-121 puts the first 20 fetched figures into the `fetch_data` tool text and the model writes the answer from them. Nothing below edits a rule. Facts are from the repo as of 2026-10-18 (branch `feat/cc-121-answer-figures`, uncommitted); inferences are marked.

## 1. Why the original design kept figures out of the model

- **Origin.** One scaffold commit, `8280f3f` (2026-08-13), `.cursor/rules/10-api-python.mdc:164-181` ("Output is not a tool either"). `d241973` (same day) copied it into the review checklist as `review-pr.md:63-64`. No ticket, no ADR, no incident; `.claude/ideation-transcript.md` never discusses it (grepped). It survived the September doc-shrink passes (`3fdcdaf`, `55efe2f`) untouched.
- **Reasons written down.** (1) Corruption: "Any value the model retypes into a tool argument is a value it can silently corrupt, and this audience is doing published research" (`:173-175`). The named flow is model-to-tool-argument copying. (2) One data channel: "The data path is `fetch_data -> response`. Never `fetch_data -> model -> response`" (`:180-181`); "Rows and margins stay in the artifact, so the model cannot retype a number" (`:126-127`). (3) The `ChartSpec` pattern: the model names a column, code supplies the value (`:176-178`). (4) Provenance: the predecessor "invented" data and was "wrong one run in three" (`.claude/DESIGN.md:20-23`; `docs/checkpoint_review.md:38`; `docs/playbooks/run-slice.md:121`: "nothing from model memory").
- **Not written down (my inference).** Context size (2,000+ row responses, `:303-305`) and log hygiene (URLs reach telemetry, CLAUDE.md Traps) probably also favoured the artifact route.
- **The unstated assumption.** A model that never sees a value cannot misstate it. The prompt said so: `62db7d4` "Do not retype estimates", `f383155` "Never invent or retype estimates. Keep answer to a concise qualitative summary".
- **What the measurement says about that assumption.** On `main`, where the model never saw a figure, 82/120 = 68.3% of answers had at least one unsupported claim (gpt-4.1 judge), 75/120 stated a figure and 0 of those were fully supported (`evidence/slice-6/cc-121-results.md:9-11`). Withholding the numbers did not stop figures in the prose; it made them come from memory, which is the exact failure the rule exists to prevent. After the change: 30.0% (53.3% under the stricter judge), not zero, and the target as filed is red. Caveats in that file: judge sees all rows (rates are lower bounds), about 2.5 points of noise.
- **Net.** The rule's aim (no model-originated values in what a researcher relies on) is intact in CC-121. Its mechanism (hide the values) was a means that did not deliver. The conflict is with the broad wording, not the narrow rationale.

**Conflicts with the wording:** `review-pr.md:63-64`; `10-api-python.mdc:126-127`, `:173`, `:180-181` (the model now reads a copy of the first 20 values and writes them into `answer`). **Does not conflict:** `AskResponse.rows/moe/geoid/universe/urls` are built in `assemble()` (`ask.py:210+`) from the artifact, not from `answer`; `comparisons[]` is computed by code (`compare.py`) and the prompt forbids model arithmetic; tool arguments are still IDs only (nothing retyped into a call); `ChartSpec` still names columns; URLs in the tool text are `str(CensusURL)`, key-redacted, test-covered; MOE, GEOID, vintage and universe are attached by code (`figures.py`) to every figure shown; the failure branch shows no figures (`test_failed_fetch_content_has_no_figures`). **Grey:** `answer` was always the one model-authored string ("Narrative is the model's native output", `:170`), so the old rule never made prose number-free by construction, only by instruction; `finish_tools()` fetches after the model has stopped, so there the model still writes without figures (documented, `ask-path.md:29-32`).

## 3. Options

**A. Narrow the rule by channel.** Case: it states what is actually protected (data fields, tool arguments, chart values stay code-sourced; reading and quoting is allowed), matches the owner's measured result, and gives Gate 2 a checkable question instead of a rule the code visibly breaks. Candidate wording for `review-pr.md:63-64` (not written anywhere):
> - Where does each number come from? `rows`, `moe`, `geoid`, `universe`, `urls`, `comparisons` and every `ChartSpec` value come from the fetch artifact or code, never from model text. The model may read the figures `fetch_data` shows it and quote them with their margin of error and universe. It types no value into a tool argument or chart spec, states no computed value, and each figure it is shown carries its own vintage's label.

Matching Cursor edits: `:126-127` "The summary is what the model reads (counts, URLs, the figures `docs/ask-path.md` lists); rows and margins stay in the artifact and the response is built from it"; `:173-175` "Numbers reach the response only through the artifact; any value the model types into a tool argument or ChartSpec can be silently corrupted"; `:180-181` "the response data path is `fetch_data -> response`; the model gets a read-only copy for prose". Do not copy the number 20 into the rule (it would drift from `figures.py`). Gate 2 then checks: response fields untouched by model text; no value in tool args or chart spec; per-year label/E/M/GEOID/universe on every figure shown; no computed value in the prompt; the reported unsupported-figure rate. Regression looks like: a tool taking a numeric argument, a `ChartSpec` carrying literal values, `comparisons` built from prose, figure text losing M or GEOID, labels from the wrong vintage (Gate 2 finding 1), or the prompt asking for arithmetic. Doc cost: about +5 lines net (1772 of 1800). Drift risk: medium. "Reads and quotes" can stretch to "reads all rows", then "computes"; the three code-only items are the fence.

**B. Keep the rule; record CC-121 as a dated, time-boxed exception.** Case: no precedent is set before CC-122 shows how computed values reach the model; exceptions stay visible as debt (the repo already treats waivers and the leakage baseline this way, `check_invariants.py` `check_no_new_exemptions`); a one-PR exception is cheaper to undo than a rule rewrite. Wording sketch: "Exception, CC-121 (2026-10-18): `fetch_data` shows the model its first fetched figures; scope ends at that tool text. Any wider use needs a new owner decision." Gate 2 checks the exception's scope and cites it. Regression: scope creep (more rows, computed values) shipped under the exception's name. Doc cost: about +4 lines, and the Cursor rule needs the same footnote or it keeps contradicting. Drift risk: high. Nothing enforces an expiry, a date-triggered test would be a validator of a rule, and the natural end event is backwards: CC-122 (compute tools) puts more values in front of the model, so it widens the conflict instead of closing it unless its results are rendered by code (see question 4).

**C. Keep the rule; render figures in code, model writes prose without them.** Case: the only option where the literal rule holds, and a structural guarantee is categorically stronger than a measured rate for an audience publishing research. Cost and why it was rejected: revert the tool text to count and URLs, append a code-rendered figure block to `answer` (about 20-40 lines in `ask.py`/`figures.py`, tests, no doc-line growth, and if it is a new `AskResponse` field then contract, client regeneration and web, where `web_src_loc` is 3349 of 3350, so an owner budget raise). The earlier ticket mechanism (code-rendered sentences plus a tokenizer and number-word parser over the prose) was replaced because it needed word lists, and a runtime check or judge call was ruled out (end of request never calls the model; p95 18.9 of 20 s). Without a check over the prose the model is again free to state figures from memory next to the code-rendered ones, which is the 68.3% baseline, and a contradiction between prose and block becomes a new silent wrong answer. Gate 2 checks no value in tool text. Regression: figures creeping back into the tool text; unsupported rate back at baseline. Drift risk: low for the rule, high for the outcome.

**D. A, then later make A enforceable by structure (reference composition).** Case: apply the `ChartSpec` pattern to prose. The model emits answer segments, text or a reference `{variable, geoid, year}`, and code substitutes value, MOE and universe, so a quoted figure is exact by construction with no regex and no extra call (Pydantic validates, "model composes, code validates"). It would also carry CC-122 results the same way. Limits: stray digits typed as text are still undetectable without a parser, so it narrows retype errors but not memory-invented figures; it needs a new final-answer schema (`domain_models` 11 of 15), prompt tokens (about 100 free), a web renderer (`web_src_loc` has 1 line free), client regeneration, and its own measurement. My estimate, not measured: 150-250 lines and its own ticket. It is not for this PR; it is what would make A's "types no value" mechanically checkable. Drift risk: lowest once built.

Which option fits which view: A if the aim is "no model-originated values in the result" and the measured gain stands; B if the owner wants the question held open until CC-122; C if a structural guarantee outranks the unsupported-rate gain; D as a follow-up under A, not instead of it.
